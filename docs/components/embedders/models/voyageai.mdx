[Voyage AI by MongoDB](https://www.voyageai.com/) provides state-of-the-art embedding and reranking models. To use its embedding models, set the `VOYAGE_API_KEY` environment variable. You can obtain a Voyage AI by MongoDB API key from the [Voyage AI dashboard](https://dashboard.voyageai.com/).

### Usage

<Note> The `embedding_model_dims` parameter for `vector_store` should match the embedding dimension of the chosen model (`1024` by default). Voyage models that support Matryoshka dimensions (the 4-series `voyage-4-large`, `voyage-4`, `voyage-4-lite`, `voyage-4-nano`, `voyage-code-4`, plus `voyage-3-large`, `voyage-3.5`, `voyage-3.5-lite`, `voyage-code-3`, `voyage-context-*`) accept `embedding_dims` values of `256`, `512`, `1024`, or `2048`. Fixed-dimension models (e.g. `voyage-finance-2`, `voyage-law-2`, `voyage-multilingual-2`) ignore it. </Note>

```python Python
import os
from mem0 import Memory

os.environ["VOYAGE_API_KEY"] = "your_api_key"
os.environ["OPENAI_API_KEY"] = "your_api_key" # For LLM

config = {
    "embedder": {
        "provider": "voyageai",
        "config": {
            "model": "voyage-3.5",
            "embedding_dims": 1024
        }
    }
}

m = Memory.from_config(config)
messages = [
    {"role": "user", "content": "I'm planning to watch a movie tonight. Any recommendations?"},
    {"role": "assistant", "content": "How about thriller movies? They can be quite engaging."},
    {"role": "user", "content": "I'm not a big fan of thriller movies but I love sci-fi movies."},
    {"role": "assistant", "content": "Got it! I'll avoid thriller recommendations and suggest sci-fi movies in the future."}
]
m.add(messages, user_id="john")
```

### Available models

Voyage AI by MongoDB exposes general-purpose, code, domain-specific, and contextualized embedding models. Any model name is accepted as `model`; the current catalog is below.

**Latest (recommended) — the mutually compatible 4-series:**

- **General:** `voyage-4-large`, `voyage-4`, `voyage-4-lite`, `voyage-4-nano`
- **Code:** `voyage-code-4`
- **Contextualized:** `voyage-context-4`
- **Domain-specific:** `voyage-finance-2` (finance), `voyage-law-2` (legal)

**Legacy (still accessible, superseded by the 4-series):**

- **General:** `voyage-3-large`, `voyage-3.5`, `voyage-3.5-lite`
- **Code:** `voyage-code-3`
- **Contextualized:** `voyage-context-3`
- **Multilingual:** `voyage-multilingual-2`

See the [Voyage AI by MongoDB model overview](https://docs.voyageai.com/docs/embeddings) for dimensions, context lengths, and per-model token limits.

<Note>
`voyage-4-nano` runs **on-device** through the `voyageai` SDK rather than the hosted API, so it needs the local extras (`pip install "voyageai[local]"`, which pulls in `torch` and `sentence-transformers`) and no `VOYAGE_API_KEY`. All other models call the hosted API. The Mem0 config is identical either way — only the model name changes.
</Note>

### Contextualized embeddings

Selecting a `voyage-context-*` model routes embeddings through Voyage's [contextualized embeddings](https://docs.voyageai.com/docs/contextualized-chunk-embeddings) endpoint.

<Note>
Each input string is embedded as its **own independent document**. Mem0 sends the batch in the endpoint's nested form (`inputs: List[List[str]]`), one single-chunk document per string, so every string resolves to exactly one embedding vector. The same document-side processing is used for both the add (document) and search (query) paths. Inputs are **not** contextualized against one another, because generic embedding callers pass unrelated texts. The call also accepts an already-chunked `List[List[str]]` batch, matching Voyage's `Union[List[List[str]], List[str]]` [input contract](https://docs.voyageai.com/docs/contextualized-chunk-embeddings).
</Note>

```python Python
config = {
    "embedder": {
        "provider": "voyageai",
        "config": {
            "model": "voyage-context-4",
            "embedding_dims": 1024
        }
    }
}
```

### Token-aware batching

For the plain text embedding path, Mem0 groups inputs into requests by estimated token count against the selected model's per-request token limit (as well as Voyage's 1000-input cap), instead of a fixed item count. A single input larger than the whole budget is sent on its own and truncated server-side.

### Config

Here are the parameters available for configuring the Voyage AI by MongoDB embedder:

| Parameter | Description | Default Value |
| --- | --- | --- |
| `model` | The name of the embedding model to use | `voyage-3.5` |
| `embedding_dims` | Dimensions of the embedding model | `1024` |
| `api_key` | The Voyage AI by MongoDB API key | `None` (falls back to `VOYAGE_API_KEY`) |
