Mem0 includes built-in support for various popular databases. Memory can utilize the database provided by the user, ensuring efficient use for specific needs.

## Supported Vector Databases

See the list of supported vector databases below.

<Note>
  The following vector databases are supported in the Python implementation. The TypeScript implementation currently supports Qdrant, Redis, PGVector, Supabase, LangChain, Oracle AI Vector Search, Azure AI Search, Vectorize, Amazon S3 Vectors, Milvus, Neptune Analytics, and an in-memory store.
</Note>

## Usage

To utilize a vector database, you must provide a configuration to customize its usage. If no configuration is supplied, a default configuration will be applied, and `Qdrant` will be used as the vector database.

For a comprehensive list of available parameters for vector database configuration, please refer to [Config](./config).

## Common issues

### Using Model with Different Dimensions

Vector store configurations default `embedding_model_dims` to `1536`, the dimension of OpenAI's `text-embedding-3-small`. Mem0 infers the dimension from the embedder you configured, so switching to a provider with a different dimension (for example Gemini with 768 dimensions) creates the collection with the correct vector size automatically.

If you set `embedding_model_dims` explicitly, it has to match the dimension of the configured embedder. Mem0 raises a `ValueError` when the two disagree:

`ValueError: Embedding dimension mismatch: the configured embedder produces 768-dimension vectors, but the 'pgvector' vector store is configured with embedding_model_dims=1536.`

Add `"embedding_model_dims": 768,` to the config of the vector_store to match your embedder. This is required for embedders that do not report their dimension, such as a custom LangChain embedder.

<Note>
  An existing collection keeps the dimension it was created with. After changing the embedder, point the vector store at a new collection or drop the old one, otherwise writes fail with a dimension mismatch instead of being stored.
</Note>
